# 静态审计族的「记账制」（豁免会过期）

> 面向前一族的 7 道静态审计：能力盘点、截图引用、文档引用、阈值收敛、仓库卫生、
> 重复实现、测试布局 / 重复。这几道的共同病根不是「规则写错」，而是**红了以后没人能修**：
> 要么常年 warn 永不拦，要么因为存量把门禁钉在红上，于是真问题进不来。

## 一条规矩：容忍必须带到期日

`scripts/audit-debt/<门禁>.json` 是这道门禁的**账本**。每条登记必须写清三样：

```json
{
  "scripts/audit-debt/check-capabilities.json": {
    "entries": {
      "<账目 id>": {
        "count": 5,
        "why": "为什么不修 / 修的时候要注意什么",
        "issue": "#209",
        "expires": "2027-01-15"
      }
    }
  }
}
```

- `why`：一句话说清这是什么问题、修法方向。写不出来的，说明它不该被容忍。
- `issue`：承接单号。没有单号的债＝没人认领。
- `expires`：**到期日，且不许超过今天 + 90 天**。到期即红，续期就是改这个日期（会进 diff）。

没有 `expires` 的登记会被门禁直接判红 —— 这一族以前那些「先 warn 后 strict」的注释
就是这么烂掉的：没有日期的容忍等于永久放弃。

## 三档判定

| 情形 | 档位 | 依据 |
| --- | --- | --- |
| 账上没有的违规（新增 / 数量超登记） | **红** | 新引入的问题没有人认领 |
| 账上有、未到期 | 提示（每次都打印，带剩余天数） | 已知、已认领、有期限 |
| 账上有、已到期 | **红** | 期限就是它的全部意义 |
| 实际比账上少（修好了但没销账 = **账实不符**） | **红**（`check-doc-refs` / `check-ui-shots`）；`check-capabilities` 仍是提示（未整合，见下）；其余门禁待逐个裁决 | **账实不符本身就是要人做决定的事**：要么销账、要么重新论证。账本只许等于现状 —— 账面比现实多，它就同时骗两个方向。见下节 |
| 账本形状不合规（缺 why / issue / expires，或期限太远） | **红** | 形状不合规的账本就是白名单 |

**第 4 条 2026-11 改过档：从「提示」改成「红」。** 原来的理由是「修的人未必是记的人 —— 正确改动
不许红」（老惯例成立的前提是「这条红有人当场能修」，而改 `src/**` 的和改 `scripts/**` 的往往不是同一个人）。

改判的理由，是这条旧理由的**前提不成立**：
- **销账不贵。** 修法只有一条 —— 从 json 里删掉那一行（登记数大于 0 但不是 0 的情况：把 `count` 改成实际的数）。
  一条 `git rm` 级别的动作，比读一份假账便宜得多。
- **账比现实多不是「多一层保险」，是账本变成一段过期叙述。** 人会照着它以为这里还没修（白跑一趟），
  也会因此高估整本账的可信度 —— 而账本的全部价值就在于「它说的话可以当依据」。
  账实不符的那一刻，它两边都在骗：骗人说「还欠着」，也骗人说「这本账可信」。
- 所以口径钉成：**账本只许等于现状**。这条与「豁免会过期」是同一条准绳的两面 —— 一头不许无限续命，
  另一头也不许挂着一笔不存在的债。

`check-capabilities` 目前仍是提示（那一族的登记是能力盘点缺陷，销账要动 `src/**`，整合留给它自己的车道）；
**口径不一致这件事本身也是债**，不许当成"已经统一了"。

## 「账面比实际多」为什么从提示改成了红（2026-11-26 裁决）

原来这一档只印一句 `ℹ 提示`，理由是「修好一处缺陷的往往不是改账本的人，把别人的正确改动
变成红灯，是这一族『改对了也红』的老毛病」。这个理由在**单次**改动上成立，但实测的代价更大：

`check:doc-refs` 记账时登记了 20 处行号漂移；文档那边把这些漂移**全部修对之后**，账本里
**17 笔**再也不会命中（其中 9 笔是生成文档重新锚定后变死的）。如果这一档只提示，那 17 笔
**谁都不会去看** —— 下一次再有人查这张表，看到的是「20 笔债还挂着」，于是要么重记一遍、
要么干脆不信账本。**「只增不减」正是豁免表烂掉的开始**，它和「没有 `expires` 的永久豁免」
是同一个病：一张没人维护的表，比没有表更坏。

所以改成红，并且给它一条**能自我证伪**的销账入口：

```bash
node scripts/check-doc-refs.mjs --prune   # 只删「原文在正文里一次都不出现」的死账；删完 review diff
```

- **只删死账**：账目 id 是 `文档::引用原文`，`--prune` 会回到当前正文里找那段原文；
  **原文还在、只是判定变绿了**的账（说明判据可能被改松，或这条引用被改成了不判定的写法）
  **一律不动** —— 那种账必须人工重新论证。这样 `--prune` 就不会变成一个「把还在违规的账
  顺手销掉」的后门。
- **销账要进 diff**：删的是账本文件本身，review 看得见少了哪几笔。
- **红消息逐条点名**：不只报「多 N 笔」，而是把每一笔 `文档::引用原文` 与「登记 N / 实际 M」
  打出来 —— 否则人还得自己去 diff 账本。

判据侧同理：这一族「容忍现状」的前提是**账实相符**。账实不符和「未记账的新违规」在输出里
共用同一段与同一个退出码（不制造第二种红）。

## 账目 id 不许含行号

行号会随正确改动漂移。用 `文件:行` 当账目 id 就等于把「现状」钉死：挪一行代码，整本账失真。
现有 id 长这样：

- 能力盘点：`类别|文件|能力名`（如 `css|src/…/MessageList.module.css|scrollbar-gutter`）
- 文档引用：`文档::引用原文`
- 截图引用：图片路径（一张图一笔）

## 自证：一条命令

```bash
npm run check:audit-selftest     # 六道门禁的 --selftest 串起来跑，≈3s
```

每道 `--selftest` 都至少四拍：**干净 → 故意违规（必红，且点名 + 给修法）→ 记账（必绿）
→ 到期（必红）**。做不出这条对照的门禁，不要相信它的绿。

「账实不符 = 红」有自己的反例拍：`check-doc-refs` 的 ⑮ / ㉑ 与 `check-ui-shots` 的 ⑦ 各造一笔
「账上登记了、现实里没有」的账，**必须 exit 1 且报「账实不符」**——否则这条新判据只是又一句注释。

`check:doc-refs` 另有九拍专门钉「账面比实际多 = 红」与 `--prune` 的边界：死账必红 → `--prune`
后必绿 → **原文还在正文里的账，`--prune` 不许删**（`node scripts/check-doc-refs.mjs --selftest`
第 ⑬~⑯ 拍）。
